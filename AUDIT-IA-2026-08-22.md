# PMG Compass — Information Architecture Audit

**Date:** 2026-08-22 · **Scope:** the Streamlit dashboard (14 pages) and the 32 tabs of `COMPASS_CCSM` behind it
**Method:** every page opened against live data on `localhost:8502`, section heights measured in the DOM, every sheet tab row-counted through gspread. No code was changed.

This audit answers three questions: **how is the app organised, where is the same thing said twice, and what should we fix first.**

---

## 1. The one-paragraph diagnosis

The app is organised by **where the data comes from** and **what scope you want**, not by **what you are trying to find out**. Scope and time period — the two things that should be *controls* — are currently *pages*: Panel is "the mission, now", Desgloses is "a zone/district/area, now", Informes is "the mission, a week you pick". They are the same report at three coordinates, and they disagree with each other. Meanwhile the thing that should organise pages — the question being asked — is scattered across a flat, ungrouped list of 14 sidebar entries with no sections, where a starved page (Embudo — see the plan's Part A), a two-metric page (Referencias) and the mission's flagship dashboard all get exactly the same visual weight.

The second-order effect is measurable. On the Panel, **60% of the vertical space is "did you turn the form in", and 24% is "how is the mission doing."**

## 4. Bugs found while auditing

These are correctness problems, not taste. Listed worst first.

### B1 — `get_weekly_ki()` returns empty for every caller, always. **(P0)**
`queries.py:261` reads the tab with `header_marker="week_end_date"`. `sheets_client.py:98` matches that marker **case-sensitively**. `WEEKLY_KI`'s header row reads **`Week_End_Date`**. The marker never matches, `_read_tab_cached` falls to its `else: return pd.DataFrame()` branch, and **34 rows of good Key Indicator data are unreachable by the app.**

Everything downstream is silently dead: `get_weekly_ki_trends()`, `get_weekly_ki_by_zone()`, `get_latest_weekly_ki()`, Panel ④, and Informes' entire Key Indicators section plus its week list.

Fix is one line — compare the marker case-insensitively (or fix the header). Verified against the live sheet: rows 1–3 are `2026-08-23 | Boca de la Costa 2 | San Pedro | … | 7 | 10 | 8 | 9 …`, i.e. the data is fine.

### B2 — Panel ④ asks the wrong tab for the wrong metrics. **(P0)**
`01_Panel.py:895` plots `flavor.nightly_highlights` keys (`bom_shared`, `church_invites`…) against `get_weekly_ki_trends()`, which returns `WEEKLY_KI` columns — only `ki_*` keys live there, so those columns can never exist. Separately, the `if trends_chart.empty` guard at `:885` also suppresses the **right-hand** KI chart, whose data (`get_weekly_ki_totals()` ← `WEEKLY_FORM_RAW`) is live today. So ④ would still be half-broken after B1 is fixed. Three defects in one 127 px section.

### B3 — Informes grades Key Indicators against the wrong week's goals. **(P0)**
`11_Informes.py:119` calls `goal_metric_key()` and reads the goal off the **same row** as the result. A week's goals are written on the **previous** week's form (`WeeklyReportForm_ES.gs:113-118`). The Panel fixed this in `8960af0` with `get_ki_goals_for_week()` (a W−7 lookup by date); Informes never got the fix and is the only remaining caller of the old pattern.

### B4 — Puntajes' effort section ignores the filter directly above it. **(P1)**
`06_Puntajes.py:1679` calls `_load_effort()` → `get_effort_data()`, which returns mission-wide `DASHBOARD_SUMMARY` rows. The Zone/District selectboxes at the top of the same tab filter `df` but never touch `effort_df`. Pick a zone and the effort numbers don't move.

### B5 — The notification bell is a dead link. **(P1)**
`design_system.py:959` emits `<a href="/Action_Center">`. The page file is `17_Centro_de_Acción.py`, so its route is `/Centro_de_Acción`. Streamlit serves **Home** for the unknown path — verified live. The one affordance present on every page goes to the wrong page, silently.

### B6 — The Action Center contradicts itself. **(P1)**
The bell's `total` includes `maintenance_issues`, but "Needs Your Action" doesn't render them. Live right now: bell reads **1**, the page reads **"Nada requiere su acción en este momento"**, and two sections lower sits `6 agent run(s) failed in the last 14 days` — in English (hardcoded f-strings at `action_center_queries.py:143-151`).

### B7 — Referencias prints impossible rates. **(P1)**
Live: Almirante Latorre **400.0%**, Los Huertos **250.0%**, Villa O'Higgins **200.0%**, Los Sauces **128.6%**. "Asked" and "Received" are independent nightly counts — an area can receive referrals it didn't ask for that day. Their ratio is not a conversion rate, and the page's headline caption ("El 37,1% de las referencias solicitadas se convirtió en una referencia de un miembro") states a causal link the data can't support.

## 5. Language and format consistency

The mission default is Spanish. These render in English **today**, in production:

| Where | What |
|---|---|
| Panel ⑦ | All 4 tiles (`TOTAL FORMS SUBMITTED`, `COMPLIANCE ALL-TIME`, `DAYS TRACKED`, `AREAS AT 100%`), both calendar legends, both captions, and the combined-compliance line — **the most-scrolled section of the flagship page** |
| Metas | The 4 section tabs: `Area Goal Customization / Mission Goals / Goal Settings / Area Expectation Settings` |
| Traslados | Both section tabs: `Schedule / Roster Update` |
| Mantenimiento | All 5 section tabs, plus the entire weekly to-do checklist |
| Puntajes | Page title `Mission Scores`, all 4 score labels, the tier legend, all 10 table headers |
| Centro de Acción | The maintenance issue messages |
| Metas intro | Names Utah Provo's Key Indicators — *"Gate, Date, New, Pew, Renew y Mate"* — **none of which CCSM collects** |

Root cause for the tab rows: `_GOALS_SECTIONS`, `_TRASLADOS_SECTIONS` and `_SECTIONS` are raw Python string lists passed straight to `st.radio` / `st.segmented_control` with no `t()` and no `format_func`. The Panel's established pattern (stable ids + `format_func`, from item 3) fixes all three.

**Number and date formats also disagree with themselves:**
- Puntajes prints `41.4` / `91.9` (US decimal point) on the same screen where the Panel prints `46,8%` / `2,55` (Spanish comma).
- Home's status pill: `8/17/26 → 8/23/26`. Informes: `16-08-2026`. Panel: `17 al 23 de agosto`. Three formats, three pages.

## 6. Policy — RESOLVED 2026-08-22: audience is Mission President + APs only

The original standing decision (set 2026-08-20) read: **pages stay open to every authenticated user, therefore per-area callouts are positive-only** — no bottom-N naming, because the missionaries named could read it themselves. The one exemption granted at the time was for **compliance** ("did you turn the form in" is a behaviour an area controls outright), scoped to compliance specifically.

Three pages named every area worst-included, on **performance**, in violation of that rule:

1. **Puntajes** — all 43 areas ranked, **with both missionaries' names**, and 42 of 43 showing `KI 0.0` (the goal-offset gap) — that scoring bug stands regardless of the policy call.
2. **Informes ③** — the same 43-area score table, sorted worst-last.
3. **Referencias** — all 43 areas ranked, including the impossible rates in B7.

**Decided 2026-08-22: the app's real audience is the Mission President and the APs only** — narrower than "every authenticated user." Under that audience, the positive-only constraint no longer applies: **naming the weakest areas, and the missionaries in them, is now permitted app-wide**, not just for compliance. All three pages above are policy-compliant as shipped; no naming change is needed on any of them.

**`auth.py`'s login allowlist stays as-is, on purpose.** `get_allowed_emails()` still grants login to all 97 `MISSION_ORG` companion mailboxes, not just the President and APs — asked directly, the user declined restricting it. The lifted rule rests on who the app is *designed for*, not a login gate.

## 7. What should move

> ⚠️ **PARTLY SUPERSEDED 2026-08-22 by `PLAN-2026-08-22.md` Part A.** Four recommendations in this section would have removed working capability and are **reversed** there: hiding **Embudo** (Tableau feeds three consumers, not one — including Desgloses' Teaching Pipeline and a 2× baptism undercount on Metas), folding **Puntajes › Actividad Diaria** (holds the app's only multi-metric chart, its only 1–120 day window, and its only raw-record dump), folding **Referencias** (Panel ⑤ is single-metric and mission-only — the fold loses the metric pairing and the per-area view), and folding **Informes** (the only page with a week picker, zone scope, and CSV export). The governing principle is now **consolidate the source, not the surface**. The rest of this section stands.

### 7.1 Group the sidebar
14 flat entries, no sections, alphabetically-by-number. A dead page and the flagship dashboard look identical. Streamlit 1.40 supports grouped navigation via `st.navigation`. Proposed (revised in the plan to keep Embudo and Referencias in nav):

```
VER          Panel · Desgloses · Informes
ANALIZAR     Puntajes · Embudo de Búsqueda · Referencias
DIRIGIR      Metas · Centro de Acción · Notas
OPERAR       Traslados · Editar Envíos · Sugerencias · Mantenimiento
             (Home = assistant, stays at top)
```

### 7.2 Collapse the three "same report, different coordinate" pages
Panel / Desgloses / Informes should share **one scope control and one period control**. Short of a rewrite, the cheap version is: give all three the same header bar, make Desgloses **default to the whole mission** instead of opening blank, and make Informes' sections read from the same functions the Panel uses (which also fixes B3 for free).

### 7.3 Moves, page by page

| Move | From → To | Why |
|---|---|---|
| Compliance rankings | Panel ⑦ → collapse to **top 5 + bottom 5 + "ver las 43"**, or move the full list to its own page | 38% of the Panel for one list |
| The 3 redundant compliance percentages | Panel ⑦ → pick **one** headline number, put the rest in an expander | Four answers, one question |
| Effort Reporting | Puntajes › Actividad Diaria → **repoint** at `effort_breakdown.py` (not delete) | Same question, worse source (D2) — repointing also fixes B4's scope bug |
| ~~Daily Trend / By Area / Raw Data~~ | ~~fold into Desgloses~~ — **REVERSED** | Holds the only multi-metric chart, 1–120 day window, and raw dump in the app |
| ~~Referencias~~ | ~~fold into Panel ⑤~~ — **REVERSED**, fix B7's math instead | Panel ⑤ is single-metric and mission-only; the fold loses the pairing and the per-area view |
| Notes | Desgloses' area view → keep the *add* box, link out for the list | Two note UIs |
| ~~Embudo de Búsqueda~~ | ~~hide until Tableau sync exists~~ — **REVERSED**, build the sync (plan Phase 3) | Tableau feeds Embudo **and** Desgloses' Teaching Pipeline **and** Metas' real baptism count (`gate` proxy undercounts ~2×) |
| App Guide | Home expander → rewrite | Lists 8 pages; there are 14. Informes, Traslados, Referencias, Sugerencias, Centro de Acción and Editar Envíos are undocumented |

### 7.4 One in-page tab idiom, not four
`st.tabs` (Puntajes) · styled `st.radio` (Metas) · the *same CSS block copy-pasted* into Traslados · `st.segmented_control` (Mantenimiento) · two `st.button`s in columns (Panel ⑦). Each was a reasonable local fix; together they mean five sub-navigations that look and behave differently. Pick the button-pair recipe (the only one that is full-width, sticky across reruns, and already handles its own selected state) and share it.
